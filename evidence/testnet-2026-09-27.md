### Real finding: repeat withdrawal on an exhausted balance is a silent no-op

A second `withdraw_remaining_bond` call on SLA 1 (balance already `0`) was attempted to see how the contract behaves. It **succeeded** (tx `0dbbb2e82da901912ec1cc55e2d05e33cee3ff73e9b74301ec9a7632ba328deb`), transferring `0` and emitting a second `bond_withdrawn` event with `amount: "0"`. This does not move any real funds and is not a fund-safety issue, but it is not rejected either, unlike `create_sla`'s analogous zero-amount guards. Recorded here as a real, previously undocumented observation, not fixed in this phase (Phase 10 is verification only, no code changes).
